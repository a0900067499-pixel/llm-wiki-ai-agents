# 何時該用 Agent？

## 先選最簡單的
- 先找最簡單的解法，必要時才增加複雜度，有時根本不需要 agentic 系統。[S5]
- agentic 系統是用「更慢、更貴」換「表現更好」，要確認值得。[S5]
- 很多應用只要把單次 LLM 呼叫（加上檢索和範例）優化好就夠了。[S5]
- agent 常常是殺雞用牛刀；流程可預測就直接寫死，系統會完全可靠。[S2]

## 三個「該用」的訊號（OpenAI）
- **複雜決策**：需要細膩判斷、例外處理，例如退款審核。[S6]
- **難維護的規則**：規則龐大複雜、改一次就容易出錯，例如供應商資安審查。[S6]
- **大量非結構化資料**：要讀文件、理解自然語言、和人對話，例如房屋保險理賠。[S6]
- 比喻：規則引擎像核對清單，agent 像資深調查員，能讀出細微脈絡（支付詐騙偵測的例子）。[S6]

## 快速判斷表
- 流程固定、可預測 → 寫程式或 workflow；流程無法事先寫死、需要邊做邊決定 → agent。[綜合: S2,S5,S6]
