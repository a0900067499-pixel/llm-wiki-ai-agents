# 五種設計模式（從簡單到複雜）

- 這五種在 Anthropic 原文中都屬於 **workflow**（流程由程式事先寫好），agent 另外獨立說明。[S5]

- **1. Prompt chaining（步驟串接）**：把任務拆成固定的連續步驟，每一步吃上一步的輸出，中間可加程式檢查關卡（gate）。例：寫大綱 → 檢查大綱 → 寫全文。[S5]
- **2. Routing（分流路由）**：先分類輸入，再送到專門的處理流程。例：客服問題分成一般問題、退款、技術支援；簡單問題給小模型、難題給強模型。[S5]
- **3. Parallelization（平行處理）**：分段（獨立子任務同時跑，例：一個模型審查輸入是否不當、另一個回答）或投票（同一任務跑多次，例：多個 prompt 檢查程式漏洞）。[S5]
- **4. Orchestrator-workers（指揮者與工人）**：中央 LLM 在執行時動態拆解任務、分派給工人、再彙整；和平行模式的差別是子任務事先不固定。例：一次要改很多檔案的程式修改。[S5]
- **5. Evaluator-optimizer（評估者與優化者）**：一個 LLM 產生、另一個評估並給回饋，反覆迭代；適合有明確評估標準時。例：文學翻譯、多輪搜尋。[S5]

## 多代理（multi-agent）
- 先把單一 agent 的能力用到極限；多 agent 會增加複雜度。[S6]
- 該拆分的訊號：提示詞邏輯太複雜，或工具太多又彼此重疊。[S6]
- 工具數量沒有固定上限：有的系統能處理 15 個以上不同工具，有的在不到 10 個重疊工具時就出錯。[S6]
- **Manager 模式**：一個經理 agent 把專門 agent 當工具呼叫（例：翻譯經理呼叫西、法、義語 agent）。[S6]
- **Handoff 模式**：同儕 agent 之間轉交控制權（例：分診 agent 轉給技術支援、業務、訂單管理）。[S6]
