挑戰與限制

title：挑戰與限制　sources：[S3, S5]　updated：2026-11-23
  • 有限的 context 長度：歷史、指令、API 說明都要塞進去；向量檢索有幫助，但不如完整注意力。[S3]
  • 長期規劃困難：長任務中遇到意外錯誤時很難調整，不如人從錯誤中學習那麼穩健。[S3]
  • 自然語言介面不可靠：模型可能輸出格式錯誤或不照指示，所以 agent 程式碼很多在處理解析。[S3]
  • 錯誤會累積：自主 agent 每一步的小錯會一路放大，成本也較高。[S5]
  • LLM 不一定能評估自己：ChemCrow（加了 13 個化學專業工具的 agent）案例中，LLM 評審認為它和 GPT-4 差不多，但化學專家明顯偏好 ChemCrow。[S3]
  • 工具設計比提示詞更重要：Anthropic 做程式 agent 時花在優化工具的時間比提示詞多；強制使用絕對路徑就消除了 agent 切換目錄後的錯誤，也就是把工具設計得「防呆」（poka-yoke）。[S5]

設計原則（對應的解法）

  • 保持簡單、讓規劃步驟透明可見、仔細設計 agent 與電腦之間的介面（ACI：工具文件與測試）。[S5]
