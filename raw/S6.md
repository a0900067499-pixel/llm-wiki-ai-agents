- Agents are systems that independently accomplish tasks on your behalf. Workflow = sequence of steps to reach user's goal (resolve support issue, book reservation, commit code, generate report).
- Not agents: apps that use LLMs without letting them control workflow execution — simple chatbots, single-turn LLM calls, sentiment classifiers.
- Core characteristics: LLM manages workflow execution, recognizes completion, corrects actions, can halt and hand control back to user on failure; uses tools within clearly defined guardrails.
- When to build: rules-based automation falls short. Payment fraud: rules engine = checklist; agent = seasoned investigator reasoning over context.
- Three criteria: (1) complex decision-making (e.g., refund approval); (2) difficult-to-maintain rules (e.g., vendor security reviews); (3) heavy reliance on unstructured data (e.g., home insurance claims). Otherwise a deterministic solution may suffice.
- Foundations: Model (reasoning), Tools (external functions/APIs; computer-use for legacy UIs), Instructions (guidelines and guardrails).
- Model selection: prototype with most capable model to set baseline, then try smaller models; set up evals.
- Tool types: Data (query DB/CRM, read PDFs, web search), Action (send emails, update records, hand off to humans), Orchestration (agents as tools).
- Instructions: use existing documents (procedures, scripts, policies); break down tasks; define clear actions; capture edge cases.
- Single-agent run loop until exit condition: final-output tool called; model replies without tool calls; error; maximum turns reached.
- Maximize a single agent first. Split when logic is complex or tools overload (some handle >15 distinct tools well, others struggle with <10 overlapping ones).
- Multi-agent: manager pattern (manager calls specialized agents as tools, e.g., translation manager with Spanish/French/Italian agents) and decentralized handoff pattern (triage agent hands off to tech support/sales/order management).
- Guardrails are layered defense: relevance classifier, safety classifier (jailbreaks, prompt injection), PII filter, moderation, tool safeguards (rate tools low/medium/high risk by read/write, reversibility, permissions, financial impact), rules-based protections (blocklists, input length limits, regex), output validation.
- Human intervention triggers: exceeding failure thresholds (retry/action limits), high-risk actions (cancel orders, large refunds, payments).
- Conclusion: start with a single agent; move to multi-agent only when needed; deploy incrementally and validate with real users.
