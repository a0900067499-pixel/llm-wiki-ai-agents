- "Agentic systems" is the umbrella term. Workflows: LLMs and tools orchestrated through predefined code paths. Agents: LLMs dynamically direct their own processes and tool usage, keeping control over how they accomplish the task.
- Start with the simplest solution; add complexity only when needed — sometimes no agentic system at all. Agentic systems trade latency and cost for better task performance.
- Workflows: predictability for well-defined tasks. Agents: flexibility and model-driven decisions at scale. Often one optimized LLM call with retrieval and in-context examples is enough.
- Frameworks help start but add abstraction that obscures prompts/responses and complicates debugging; start with LLM APIs directly and understand underlying code.
- Building block: augmented LLM = LLM + retrieval + tools + memory, with a clear, well-documented interface.
- Pattern 1 Prompt chaining: sequential steps, each call uses previous output; programmatic gates check intermediate output. Use when task decomposes into fixed subtasks; trades latency for accuracy. Example: outline → check outline against criteria → write document.
- Pattern 2 Routing: classify input, send to specialized follow-up. Example: customer service — general questions, refunds, technical support; easy questions to small model, hard ones to capable model.
- Pattern 3 Parallelization: sectioning (independent subtasks in parallel, e.g., guardrail model screens input while another responds) and voting (same task multiple times, e.g., several prompts review code for vulnerabilities).
- Pattern 4 Orchestrator-workers: central LLM breaks task down at runtime, delegates to workers, synthesizes. Unlike parallelization, subtasks not predefined. Example: coding changes across many files; multi-source search.
- Pattern 5 Evaluator-optimizer: one LLM generates, another evaluates and gives feedback in a loop. Use when clear evaluation criteria exist and iteration adds measurable value. Example: literary translation; multi-round search.
- Autonomous agents: start from human command/discussion, plan and operate independently, get "ground truth" from environment (tool results, code execution) each step, pause for human feedback at checkpoints/blockers; typically LLM using tools in a loop with stopping conditions such as max iterations.
- Risks: higher cost, compounding errors; test extensively in sandboxed environments with guardrails.
- Three core principles: simplicity; transparency (show planning steps); carefully crafted agent-computer interface (ACI) via tool documentation and testing.
- Appendix: customer support and coding agents (verifiable with automated tests; human review still essential).
- Tool tips: write tool descriptions like a docstring for a junior developer; test many inputs; poka-yoke tools. Example: requiring absolute file paths removed errors after the agent changed directories; more time spent optimizing tools than the prompt.

## 補充擷取（2026-11-23，簡報檢視後的缺口迴圈）
- The five patterns each have a heading beginning with "Workflow:" (Workflow: Prompt chaining / Routing / Parallelization / Orchestrator-workers / Evaluator-optimizer); "Agents" is a separate section.
- Poka-yoke your tools: change tool arguments so mistakes are harder to make; the model made mistakes with relative filepaths, so absolute filepaths were required and then used without error.
- Testing: carry out extensive testing in sandboxed environments, along with appropriate guardrails (in the context of autonomous agents).
